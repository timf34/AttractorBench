# unsteering/ — steering-removal ("unsteer") experiment family

One question, three intervention types: **apply a persona intervention for the first K turns of
a two-instance ai2ai conversation, then remove it, and watch whether the attractor basin
persists.** If the trajectory continues after the intervention is gone, the basin has become
self-sustaining in the transcript (context self-conditioning) rather than being held open by
the steering.

## The three arms

| arm | intervention (turns 1..K) | after turn K | condition name | status |
|---|---|---|---|---|
| **pvec** | persona-vector activation steering (baked vLLM variant) | raw base model (2nd endpoint) | `<trait>_pvec_unsteer_k<K>_ai2ai` | DONE — `configs/pvec_unsteer_ai2ai.py` + `run_fixedk_pipeline_on_pod.sh` |
| **prompt** | `<trait>_rich_persona` system prompt | system message rewritten to `helpful_assistant` (history preserved) | `<trait>_prompt_unsteer_k<K>_ai2ai` | `unsteering/prompt_unsteer_ai2ai.py` |
| **lora** | persona LoRA adapter (`local/<trait>`) | raw base model (`local/<BASE_MODEL>`, same vLLM server) | `<trait>_lora_unsteer_k<K>_ai2ai` | `unsteering/lora_unsteer_ai2ai.py` |

The `_unsteer_k<K>_` name segment (underscore before "unsteer") is load-bearing: downstream
regexes (`run_onset_judge.py`, `attractor_internals/`) parse K out of it.

## Shared design (all arms)

- mode `two_instance`, seed set `goodness_opener_v1`, temp **0.7**, top_p 0.9, 10 seeds,
  30 turns, K ladder **2 4 6 8 12 16** (same as the pvec fixed-K sweep).
- `switch_turn=K` counts TOTAL messages (A speaks odd turns, B even); the switch applies to
  both sides at turn K+1.
- Since the runner change accompanying this package, every unsteer condition JSON records the
  switch in its payload: `switch_turn`, `model_a_post` / `model_b_post`,
  `system_prompt_key_post` / `system_prompt_post`. (For prompt-unsteer runs this payload record
  is the ONLY trace — the per-turn `model` field never changes there.)
- Controls already exist, none are re-run: steer-forever = `<trait>_pvec_c*_l16_ai2ai` /
  `<trait>_richprompt_ai2ai` / `<trait>_ai2ai`; never-steer = `base_ai2ai` / `base_pvec_ai2ai`.

## Traits

- **prompt arm — all 12** (every trait has a `<trait>_rich_persona` prompt): loving goodness
  poeticism sycophancy nonchalance remorse sarcasm honesty sincerity mathematical humor
  impulsiveness.
- **lora arm — 10** (no sincerity/honesty; those are prompt-only, no adapter exists in
  `maius/llama-3.1-8b-it-personas`): goodness humor impulsiveness loving mathematical
  nonchalance poeticism remorse sarcasm sycophancy.

## How to run

### prompt arm — local, no GPU (OpenRouter-served Llama-3.1-8B-Instruct)

```bash
# needs OPENROUTER_API_KEY in .env (generation + judges)
bash unsteering/run_prompt_unsteer.sh
TRAITS="nonchalance loving" KS="2 8" bash unsteering/run_prompt_unsteer.sh   # subset
# one cell by hand:
TRAIT=nonchalance SWITCH_TURN=4 python -m attractorbench.runner --config unsteering/prompt_unsteer_ai2ai.py
```

### lora arm — GPU pod (one vLLM serves base + adapter simultaneously)

```bash
git clone https://github.com/timf34/AttractorBench.git && cd AttractorBench
cp .env.example .env && nano .env      # OPENROUTER_API_KEY for the judges
SHUTDOWN=stop SAVE_TO_GIT=1 bash unsteering/run_lora_unsteer_on_pod.sh
```

The pod script serves one trait at a time:
`vllm serve <BASE> --enable-lora --max-lora-rank 64 --lora-modules <trait>=./adapters/<trait>`
exposes BOTH the base HF id and the adapter name on one endpoint, so the harness's mid-run
model switch (`local/<trait>` -> `local/unsloth/Meta-Llama-3.1-8B-Instruct`) needs no second
server.

### pvec arm (reference)

Already generated by `run_fixedk_pipeline_on_pod.sh` (two vLLMs: baked-steered + base);
transcripts under `results/pvec_unsteer/` and flat `results/<trait>_pvec_unsteer_k*_ai2ai`.

## Where results land

Both drivers generate into flat `results/<cond>/` (the runner's default), run the analysis
pipeline (stage-1 deterministic, stage-2 judge via `run_judge.py`, per-run onset/fate judge via
`run_onset_judge.py`), then move the finished dir:

- prompt arm -> `results/prompt_unsteer/<cond>/`
- lora arm  -> `results/lora_unsteer/<cond>/`

All downstream tools (`run_onset_judge.py`, `attractor_internals/`, `summarize.py`,
`publish_steering.py`) resolve conditions at either level (flat or one subfolder down).
Existing conditions are skipped on re-run; the runner itself no-clobbers (timestamped siblings).
